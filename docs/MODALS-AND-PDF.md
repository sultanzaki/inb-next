# Complete record loading and formal PDF exports

Record detail dialogs use a shared loading boundary. ERP dialogs reveal the record body as soon as the primary read finishes. Document controls, linked documents and readiness retain visible section skeletons and retry controls; slow history no longer holds the entire record hostage. Controls do not render their actions until their own data is ready, and mutations still enforce business rules in the database. Product specifications wait for the current specification read, while version history loads independently. The ERP boundary keeps mounted sections stable instead of remounting them when the primary loading flag changes. ERP reads and specification-history requests have a 20-second client timeout. Main-record reloads hide the body until refreshed; subsequent section pagination/rechecks use their own loading skeletons.

The boundary applies to ERP/Sales/Warehouse/Production records, Finance and Service details, Growth record details (including Purchase), product specification details and audit details. Existing form editing and business approvals are unchanged. Skeleton animation respects reduced-motion preferences.

ERP PDFs share an A4 company header, legal company name, counterparty/reference block, shaded table headers, right-aligned numeric columns, grouped totals and per-page document references/page counts. Normal table rows remain together when they fit; oversized descriptions continue with repeated headers. Totals are reserved as a block. Snapshot identities and exact decimal strings remain authoritative. Finance uses its own due date, omits unknown tax percentages, and supports amount-only payment/credit documents without fictitious goods rows. No company address, bank account or signature image is invented. Existing approved COA layout and issuance proofs remain unchanged.

Validation: unit tests cover frozen identities, decimal precision, document text bounds, multipage content, PDF metadata and Finance due dates. `TEST_RECORD_LOADING_ONLY=1 npm run test:e2e` delays primary and dependent requests independently, checks that primary data appears while linked documents are still loading, focus does not refetch fresh data, and section failures recover, and checks mobile layout/accessibility. The full production browser suite covers existing conversion/approval/preview flows.

## Read latency improvements

ERP GET handlers start independently protected database reads alongside the application session check. No response is released before the session check succeeds; exports/download audit writes wait for the authenticated actor. Missing/malformed session cookies are rejected before any read. Existing database session/module/RBAC guards remain intact. POST writes keep sequential authorization. `Server-Timing` exposes overlapping `session`, `read` and overall `total` milliseconds so deployment latency can be measured without exposing SQL or identities.

Concurrent identical browser reads share one in-flight request. Results are removed on completion; there is no cross-user or persisted cache of financial balances, permissions or readiness. Each subscriber can cancel independently, and the shared fetch is aborted when the last reader leaves. Mutations invalidate in-flight sharing before/after the write, ensuring refresh does not join a pre-write read. Returning focus does not refetch data loaded within the last 30 seconds; explicit refresh and mutation refresh remain immediate. Search debounce does not delay record-by-ID requests. Excel code is loaded only for XLSX export, not eagerly on every ERP detail request.

These changes remove sequential network waits and redundant reads; production latency and region placement still require deployment measurement. No database migration is needed.

Local production-build spot check (synthetic Sales Order, local Postgres/PostgREST): server-side `total` was 20.4 ms for detail, 47.2 ms for controls and 42.7 ms for document flow during concurrent requests. These are diagnostic samples, not production latency guarantees; database/session work overlaps rather than adding sequential network round trips.

Download/export controls share a synchronous request lock, visible busy states and a preparation toast. CSV and Excel controls lock together; COA and ERP PDF downloads stay busy until the response body is ready. Failures restore the controls for retry; unmount cancels the fetch and timeouts stop indefinite preparation. Server-provided filenames are retained and sanitized. `TEST_DOWNLOADS_ONLY=1 npm run test:e2e` holds an export response to verify same-tick double-click protection, cross-format locking, filename delivery, error recovery and mobile fit.
